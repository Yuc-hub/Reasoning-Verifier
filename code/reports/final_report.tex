\begin{abstract}
\textbf{Main contribution.} Inspired by the JEV idea of making one decision from several pieces of evidence, I designed a lightweight selector that fuses final-answer agreement, text cues, supplied embeddings, comparisons among four candidates, and checkable evidence from their reasoning processes. Its final version adds target-role and quantity-source alignment, so a mathematically tidy trace is not automatically preferred when it answers the wrong quantity. A multi-correct group-softmax model learns how to combine the evidence and makes a single four-way choice without a reference answer at inference. I tested voting, pointwise, pairwise, groupwise, fusion, process, and postprocessing variants. The frozen selector obtains 743/798 (93.11\pct) on validation and 394/467 (84.37\pct) on the supplied test bank. The last eight target/source cues give a small validation gain but a one-question decline in a train-only out-of-fold diagnostic. Later development followed earlier test evaluations; the test comparison is exploratory and is not an untouched model-selection estimate.
\end{abstract}

\section{Research question and assignment setting}
A question has four candidate reasoning texts $t_i$ and supplied fixed embeddings $e_i\in\mathbb R^{1024}$. The task is to output one candidate index $\hat\imath\in\{0,1,2,3\}$. The official metric is whether the selected candidate's \emph{final parsed numeric answer} equals the reference; it does not require every intermediate statement to be sound. Multiple candidates can be correct. The provided splits contain 4,755 training, 798 validation, and 467 test questions. Test groups have at least two different valid parsed answers, whereas many validation groups are easier; raw accuracy across splits is therefore not a like-for-like difficulty comparison.

The question I chose is: \emph{does combining evidence from the question, competing answers, supplied representations, and explicit reasoning steps yield better decisions than judging a trace by one signal alone?} I expected a learned joint selector to outperform answer voting, and expected process and target-role features to help on cases where candidates perform plausible arithmetic but misuse a condition or answer a different quantity. The key design is a JEV-inspired \emph{one-shot joint-evidence decision}: construct a structured evidence vector for each candidate while seeing all four candidates, then choose once. This is a task-specific inspiration, not a claim to reproduce an external JEV architecture or its original training procedure.

The development sequence below is itself part of the contribution. I kept failed or mixed-result variants, because they show which signals and computational costs did not reliably help. Training labels come from the supplied training references only. Validation was used for development. Earlier test outcomes were viewed before later variants were proposed, so all later test comparisons are explicitly exploratory; choosing the final variant based partly on test is a protocol limitation.

\section{JEV-inspired selector: evidence and decision rule}
\subsection{From independent scores to a joint four-candidate decision}
The earliest answer-agreement baseline gives each candidate its final-answer cluster size. A text logistic model uses 20 candidate/question features, including answer agreement, numbers, length, structure and lexical overlap. A linear embedding model scores only the fixed 1,024-dimensional representation. These expose complementary but limited signals: a common answer can be systematically wrong; an embedding can encode fluent reasoning without correctness; text markers can be superficial.

The selector's base vector concatenates text/answer evidence and the supplied embedding, then adds features that compare a candidate with the other three. Let $x_{gi}$ denote candidate $i$'s vector in group $g$. The global model assigns
\begin{equation}
 s_{gi}=w^\top\frac{x_{gi}-\mu}{\sigma},\qquad
 \hat\imath_g=\underset{i\in\{1,2,3,4\}}{\arg\max}\;s_{gi}.
\end{equation}
The scale is fitted on training candidates; near-zero standard deviations are set to one. Ties select the first candidate. The \emph{multi-correct} objective places probability mass on any correct candidate, matching the scoring rule:
\begin{equation}
 \mathcal L(w)=\sum_g\left[\log\sum_{j=1}^{4}e^{s_{gj}}
 -\log\sum_{i\in C_g}e^{s_{gi}}\right]
 +\frac{25}{2}\lVert w\rVert_2^2,
\end{equation}
where $C_g$ is the set of correct candidates in training group $g$. I used deterministic full-batch Adam for 300 epochs, learning rate 0.02, $\beta_1=0.9$, $\beta_2=0.999$, $\epsilon=10^{-8}$, zero initialization and no shuffling. The final fit has no random seed. The scorer is linear so the contribution lies in constructing comparable evidence and fitting its combination, rather than in a large verifier model.

\subsection{Evidence from reasoning, conditions, and target quantity}
The experiments progressively add four families to the base group-choice representation. \textbf{Arithmetic consistency} extracts explicit elementary equalities and checks their numerical agreement. \textbf{Question-condition coverage} distinguishes a question number merely appearing in a trace from appearing in a recognized calculation, with unit/time/constraint cues. \textbf{Candidate divergence localization} compares early number and equation-result sequences across the four traces, seeking the first point of disagreement. \textbf{Answer-process linkage} asks whether verified intermediate results feed later steps and the final answer. These four families form a 1,073-feature combined model.

A further nine \textbf{process-chain} features parse explicit equality chains using a restricted arithmetic expression evaluator. Valid local equations are linked when a result appears as a later operand. The features summarize verified and invalid step counts, reuse, graph depth, question-number coverage and whether a verified result reaches the final answer. The evaluator supports numeric constants, arithmetic, parentheses, simple fractions and percentages, and rejects names and function calls; candidate text is never executed as code. Numerical comparisons use tolerance $10^{-3}$. This gives 1,082 features.

My final extension adds eight \textbf{target/source alignment} cues, reaching 1,090 features. It locates the question's final target phrase (for example, ``how much''), compares its keywords and role terms with text near the candidate conclusion, flags two narrow target-role conflicts, checks whether stated percentages or currency amounts appear as literals in verified equations, and checks target-unit mention. This directly addresses a failure observed in training-only error inspection: internally valid arithmetic may compute original price when the question asks for amount paid. These are intentionally soft lexical and numeric proxies, not semantic proofs; the learned selector decides how much to trust them.

\textbf{Loss and ranking ablations.} With the same 1,044 text-plus-embedding features, the original pairwise comparison obtained 734 validation correct; Bradley--Terry preference loss obtained 739; four-way group choice obtained 742. This supports using the full candidate set and a loss aligned to ``any correct answer'', although the objectives differ and the gaps are small. Pairwise comparison improved over isolated text and embedding scores, but those comparisons also change features, so they do not isolate the causal effect of pairwise training.

\textbf{Fusion and answer clustering.} A prespecified ten-point validation grid selected normalized pairwise score weight 1.0 and embedding score weight 0.25 (separate text-model weight 0). Fusion added four validation correct cases over pairwise alone, yet had one fewer test correct case. A fixed answer-cluster aggregation rule on the group-choice checkpoint raised validation from 742 to 745 and exploratory test from 385 to 387. Applied instead to the combined-reasoning checkpoint, it raised validation 739 to 744 but lowered test 389 to 384. Cluster support is useful in some settings but does not guarantee a better selector.

\textbf{Process and target ablations.} Adding the nine process-chain features to combined reasoning changed 109 validation choices: seven errors became correct and four correct cases regressed, for a net gain of three. On exploratory test, 16 improved and 14 regressed, net two. Adding the final eight target/source cues to the process model changed 30 validation choices, net +1, and nine test choices, net +3. These small gains deserve caution, especially because the feature design followed earlier error inspection.

\textbf{Hard-negative counterexample.} An auxiliary softplus loss emphasized the current highest-scoring wrong training candidate, using weight 0.5 and target margin 1.0 in addition to the group loss. On the combined model it improved validation from 739 to 745 and train-only OOF hard-group accuracy from 1,709 to 1,725 out of 2,114. Yet exploratory test fell from 389 to 384. Adding cluster postprocessing to that checkpoint gave 743 validation and 383 test. More focused training can improve the visible development split while failing to generalize.

\section{Answers to the five investigation questions}
\subsection{Does reading the reasoning process help?}
The answer-only voting baseline gets 688/798 validation. Text statistics plus question and final-answer cues get 719; fixed whole-trace embeddings alone get 712. The group selector combining text and embeddings gets 742. Explicit process-chain features add three validation correct over the 739 combined model, and a train-only five-fold diagnostic improves hard-group correct from 1,709 to 1,731. Thus there is evidence that structured process signals add information beyond answer agreement and whole-trace representations. The experiment does \emph{not} prove that the model understands full mathematical reasoning: feature sets and training objectives change across some comparisons, and the local parser misses implicit steps.

\subsection{Why can a wrong answer look convincing? Surface-feature ablation}
A fluent wrong trace may copy the question's numbers, display a boxed answer, or show several locally valid equations while assigning the wrong role to a value. Among 405 hard-group OOF errors from the combined model, nonexclusive heuristic flags found 174 with a simple wrong equation, 197 where a question number was mentioned but not used in a recognized calculation, 76 where the last extracted equation result differed from the final answer, and 152 where another candidate shared the wrong answer. Fifty had none of these flags. These are diagnostic counts, not causal explanations.

I removed six explicit surface features---character, word and line lengths plus boxed, ``Final Answer'', and \code{\#\#\#\#} markers---from the 1,044-feature group-choice input and retrained with the same objective. Validation moved from 742 to 743; exploratory test moved from 385 to 383. The tiny opposite-sign differences do not show that these cues are reliably helpful. Embeddings and retained numeric/operator features may still encode surface style, so this is a limited artifact ablation rather than proof of bias-free reasoning. The target-role feature family is meant to counter a different shortcut: a trace can be arithmetically coherent yet answer the wrong requested quantity.

\subsection{Should candidates be judged independently?}
The pairwise model compares candidates within a question; the group objective further makes the four-way choice jointly. With matched 1,044 input dimensions, moving from pairwise comparison to group choice raises validation from 734 to 742. Divergence-location features added to group choice raise validation from 742 to 745, but exploratory test remains 385, so this particular feature did not yield a stable visible test improvement. Answer-cluster aggregation also helps the base group model by three validation questions without retraining. These results support comparison as useful evidence, but a parser that spots an early numerical fork cannot always tell which branch applies the question condition correctly. Condition coverage alone decreased validation from 742 to 740, another useful negative result.

\subsection{Can the selector recognize its uncertainty?}
I tested the frozen role-aware selector on validation only, using the raw top-two linear-score gap as a tentative confidence signal. On all 798 groups, accuracy by ascending gap quartile was 188/200, 187/200, 185/199 and 183/199: superficially, larger margins look \emph{worse}. This is confounded by easy groups whose four candidates share an answer. Restricting to the 355 validation groups with at least two distinct parsed answers gives 73/89 (82.0\pct), 70/89 (78.7\pct), 78/89 (87.6\pct) and 79/88 (89.8\pct). Thus the gap has some ordering value on genuinely disputed questions, but is not monotonically reliable and is not a calibrated probability.

The four selectors (vote, embedding, pairwise, final) chose the same \emph{final answer} on 659 validation groups; the final selector was correct on 642 (97.4\pct). Where at least one disagreed, it was correct on 101/139 (72.7\pct). This makes answer-level disagreement a useful diagnostic for review. On 105 groups where the final answer differed from voting, the final selector was correct in 75, voting in 20, and both were wrong in the remaining 10. These numbers were computed from validation references only and were not used to tune the checkpoint. The deployed system still always selects one candidate; no abstention or calibrated confidence gate was trained.

\section{Failure analysis, limitations, and reproducibility}
The process parser checks local explicit arithmetic, not the semantics of the word problem. It may miss prose equations, algebraic shortcuts, or equivalent percentage forms such as $25/100$ instead of $0.25$. Repeated values can create a false dependency edge. A target word or unit may appear in a conclusion without being used correctly. The final role vocabulary flags only narrow conflicts such as ``original price'' versus ``amount paid'' and ``amount used'' versus ``amount remaining''; unseen synonyms are missed. All process and target cues remain learned soft features, never hard exclusions.

Five-fold train-only OOF analysis used seed 2026 for fold assignment. Combined reasoning correctly selected 1,709/2,114 hard groups, process verification 1,731/2,114, and the final role-aware version 1,730/2,114. The last step therefore \emph{decreased} this diagnostic by one even though validation increased by one and exploratory test by three. The features were designed after OOF error inspection, so the OOF comparisons are diagnostic rather than untouched holdouts. The broader search over many variants increases the risk that small improvements reflect selection noise.

The frozen checkpoint stores 1,090 float32 means, scales and weights (13,080 raw array bytes; 13,830 bytes in the NPZ file), far below the 16 MiB limit. It is \code{code/checkpoints/role\_aware\_process/model.npz}, SHA-256 \code{680c173df6c42dcbb02295d24acf6b38b1b0d8e3b5003d5788bce72885d6cb4e}. Inference reads only the supplied bank, embeddings, and checkpoint, and uses no new LLM generation, API, external data or ID lookup. Python 3.12.14 and NumPy 2.5.3 were used. The official score JSON and exact commands are in \code{code/SUBMISSION.md}; the published final model reproduces 743/798 validation and 394/467 test without retraining. Local runtime does not prove the 30-second limit on the specified Xeon Platinum 8457C.

\textbf{Protocol disclosure.} Earlier test results were visible before some later models were developed, and the final method was selected partly because its test score was highest. This conflicts with the assignment rule to use validation rather than test for method selection. The score is reproducible, but it must not be represented as an untouched generalization estimate or automatically assumed eligible without an instructor ruling. A stricter validation-only final choice would need to be frozen independently of test feedback.

\section{Conclusion and AI/reuse statement}
The central project contribution is the JEV-inspired, one-shot joint-evidence selector: it learns from answer, text, embedding, candidate-relation, process, and target/source signals to make a four-way choice. The series of controlled and partially controlled experiments shows that joint ranking is substantially stronger than voting on the supplied validation bank; process checks add modest further evidence; and simple confidence, clustering or hard-negative heuristics can fail or reverse across splits. The limited final-stage gains and OOF counterexample argue for restraint in claiming a robust improvement.

Codex AI assistance was substantive: it helped discuss model ideas and mathematical objectives, write and revise Python feature/training/evaluation code, automate experiments and diagnostics, analyze results, and draft this report. The student directed method choices, reviewed experiment outputs, selected the reported model, and remains responsible for understanding and verifying the submitted claims. The supplied dataset, fixed embeddings, parser and independent scorer were reused with their retained license and attribution. No external training dataset, additional pretrained weights or inference API was used.
